# 荔园环骑 1.8.0 · 顺峰山公园与站点旅行

## 游玩入口

自由骑行时，先按当地的「到站」按钮，到站后按「选择目的地」。深大站、UCL 旅行站、顺德牌坊广场均可直接前往其余两站。已在站点范围内时只需选择目的地。选择前可以返回，旅行沿用当前车辆与改装。顺德首发一张自由骑行图和一场固定计时赛，复用原计时线、成绩、影子和手动回归逻辑。种子赛、校园闪送、联机房间仍在原两张地图进入。

## 游戏尺度与取舍

中心线长 **1,072.74 游戏米**，约为活动报道里程的 **21.5%**。用闭合样条重画湖岸，缩短桂海芳丛到西岸、西南岸、伏波桥两头的连接段以及塔侧回程。没有活动 GPX、各段实测里程、桥梁测绘方位角或纵断面，故下表只列游戏里程，各段不能用统一比例换算回实地。西岸林荫、南岸开阔段是游戏分段名。

| 经过地点 | 累计游戏米 | 本段游戏米 |
| --- | ---: | ---: |
| 牌坊出发 | 0.00 | — |
| 桂海芳丛 | 116.64 | 116.64 |
| 西岸林荫 | 308.80 | 192.15 |
| 南岸开阔段 | 490.87 | 182.07 |
| 伏波桥桥中 | 702.97 | 212.10 |
| 青云塔山脚 | 907.99 | 205.02 |
| 牌坊冲线 | 1,072.74 | 164.76 |

- 牌坊以三组檐顶、前后石柱、牌额和悬柱建模。广场铺装约 42 × 52 游戏米，可从柱间骑过。五行桥不在本圈骑行路段。
- 伏波桥取九孔侧影，桥位设在青云湖与另一侧水面的交汇处。游戏内桥轴向东北，九孔石跨共 54 游戏米。按照片里桥中较高、引桥平顺的轮廓，用 84 米长余弦纵断面估算，最大抬升 1.72 米、峰值坡度约 6.4%。桥面、栏杆、赛道标线、车轮高度与坡度读取相同几何。其余环湖路段按近水平处理。
- 园路半宽约 3.02–4.15 游戏米，桥上半宽 3.35 米。通行区取路带和牌坊广场，树带、山体和园外楼群为游戏视角下的简化布景。桂畔湖仅表现交汇水面，首版不含第二圈。
- 青云塔设于牌坊东南的山头，以七层八角砖塔区别于湖心青龙阁。按游戏桌面跟车视点沿正向每 4 米抽样，对塔身与塔顶两个目标点做树冠三角形射线检测。在 780–788 米可见，792–824 米两点均被林木遮挡，828–864 米重新可见，868 米处部分遮挡。里程与遮挡来自游戏，实际树冠密度和季节有差异。

## 开发与构建

| 入口 | 职责 |
| --- | --- |
| `ride-update/qingyun.js` | 道路控制点、行驶宽度、路面和湖岸、桥高与栏杆、分块静态场景、检查点和小地图/大地图。按原引擎的 12 米街道网格查询碰撞候选。 |
| `ride-update/station-travel.js` | 读取地图注册表生成目的地选择器，保留到站判定、取消与旅行锁。切图仍走原场景加载、资源释放和车辆初始化流程。 |
| `ride-update/build.py` | 在第 12 层注册第三地图，接入路面/地形、障碍物、地图、赛道、勋章及版本号。渲染继续使用 32 米静态网格分块、共享缓冲与视锥裁剪。 |
| `online/server.mjs` | 读取旧存档时优先检查 1.7.0，再按原版本顺序回退。 |
| `ride-update/verify-park.mjs` | 完圈、每 0.25 米中心与两边可骑性、桥栏/岸外禁入、山体侵入行车面及塔身遮挡。 |
| `ride-update/verify-park-browser.mjs` | 由原浏览器测试入口传入 Chrome 会话，验证旅行、取消、地图、三种视口的完圈和稳定帧资源计数。 |

在项目根目录运行 `python szu-litchi-dev/ride-update/build.py` 生成桌面发行目录与手机单文件。环线专项运行 `node szu-litchi-dev/ride-update/verify-park.mjs`，浏览器运行 `node szu-litchi-dev/ride-update/verify-1.6.0.mjs --park`。可用 `CHROME_PATH` 指定 Chrome，用 `PARK_QA_DIR` 指定本机截图目录。

## 已验证与负责人回归

Chrome 无头浏览器，SwiftShader 软件 WebGL2，FXAA、快速分辨率，按日间同一位置的跟车镜头测量。每处预热 5 帧，随后统计 20 个帧间隔，表中为 P50 / P95 毫秒。此项测量覆盖桌面渲染与手机视口模拟，真机 GPU 与温控需单独实测。

| 视口（渲染像素） | 回望牌坊 | 西岸林荫 | 进伏波桥 | 桥后树带 | 塔侧湖岸 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 桌面 1280×720（893×420） | 46.3 / 50.2 | 46.1 / 49.0 | 44.2 / 46.6 | 61.4 / 63.9 | 58.6 / 62.2 |
| 手机竖屏 390×844（275×519） | 16.6 / 18.6 | 17.1 / 20.6 | 17.1 / 18.9 | 25.5 / 29.2 | 21.0 / 22.3 |
| 手机横屏 844×390（617×224） | 24.1 / 25.7 | 22.0 / 23.7 | 22.1 / 24.1 | 32.8 / 34.2 | 33.1 / 35.2 |

15 组稳定帧样本内，WebGL Buffer 创建和释放均为 0，WebGL 错误为 0。三种视口的浏览器完圈均为 100.771 秒，计时与模拟步长一致。已对比 1.7.0 的 16 条固定路线，影子布局键与记录键逐条一致。

- 发现并修复出桥处路宽突变造成的边缘误挡。调整西岸山体，避免跟车视角中山坡穿过路面，增加山体与行车面相交检查。
- 固定步长骑行通过起点、5 个中途点、终点，用时 88.630 秒。浏览器三种视口用同一套转向、油门和刹车输入驱动实际计时赛，均按顺序完圈，未使用回归。手机横、竖屏另用浏览器触摸事件验证自由骑行加速。
- 桌面覆盖三站六个直达方向；手机覆盖深大 → 顺德 → UCL → 深大。复核取消旅行、自由骑行地图，以及原两张地图的碰撞索引、路线指引、固定/周赛和存档恢复。
- 从源码 ZIP 解压后重建 12 层，桌面 8 个文件、手机单文件均与发行物逐字节相同。原地图友人影子与房间 API 回归通过。当前测试环境拒绝连接 127.0.0.1，因此启动器打开本地网页后建房、三人 WebRTC 完赛这一组合仍待本机复查。三视口环线测试使用桌面拆分文件和手机离线单文件。
- 最终人工回归由项目负责人执行。建议骑自己的改装车，进出桥各贴两侧栏杆，试西岸窄弯会车视野与贴湖侧边界，核对塔在出林后的方向及牌坊冲线计时。用手机真机横竖屏分别复查触控、发热后的流畅度和回站。计时赛偏离线路后按原按钮手动回归。
